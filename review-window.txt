The Procedure — pre-release review window

Version: 0.4.0
Last modified: 2026-07-27

Project state:
Content-complete pre-release.

Release gate:
External playtest feedback required before 1.0.0.

Review standing before 1.0.0:
Corrections, defects, accessibility failures, cold-run playtest pressure, known errata changes, resolved public-trace defects, broken public traces, reuse-boundary failures, source/provenance/artifact discrepancies, warmed doorway regressions, recovery failures, account-gated intake limitations, and uncategorized observations filed before the 1.0.0 release are part of release review, not post-release noise.

Correction surface:
https://github.com/josephusm/the-procedure/issues

Structured intake:
https://github.com/josephusm/the-procedure/issues/new/choose
Defects, accessibility failures, public trace/provenance discrepancies, and cold-run playtest feedback have separate forms. Cold-run playtest pressure has release standing when it names a weak case, broken ending, warmed doorway, unreadable surface, or drag point that should interrupt 1.0.0.

Uncategorized intake:
https://github.com/josephusm/the-procedure/issues/new
Blank issues remain enabled for observations that have standing before they fit a form. Classification is useful; it is not a prerequisite for the first sentence.

Account boundary:
GitHub issue filing may require a GitHub account or active session. Blank issues remove the pre-classification gate; they do not remove the account gate. If that boundary prevents a release-relevant defect, accessibility failure, trace discrepancy, or cold-run pressure mark from entering review, the boundary itself is part of pre-1.0.0 review.
