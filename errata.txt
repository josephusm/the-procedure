The Procedure — errata and correction-history trace

Version: 0.4.0
Last modified: 2026-08-05

Current known errata:
No unresolved release-blocking gameplay defect is recorded in the public issue surface as of 2026-08-05.

Latest resolved public-trace defect:
On 2026-07-25, the live artifact manifest was reachable but malformed: it used literal `\n` separators, so the checksum trace was not properly line-readable. The Pages workflow now writes real newline separators, and the live sample hashes verified against served files after deployment.

Known correction-surface limitation:
GitHub issue filing may require a GitHub account or active session. Blank issues remain enabled and keep observations from being forced into a category before the first sentence, but they do not create a no-account intake route. If that boundary blocks a release-relevant defect, accessibility failure, trace discrepancy, or cold-run pressure mark, the boundary itself belongs in pre-1.0.0 review.

Known review-response limitation:
No external pre-release issue is currently open. When one is filed, the release review route should leave a public response, closure reason, linked commit, release decision, or errata/correction-history entry before 1.0.0. Silent ingestion would be a public-trace defect.

This is a current trace, not a promise. New defects, accessibility failures, public trace discrepancies, unreadable or client-bound trace surfaces, source/artifact mismatches, reuse-boundary failures, continuity-exit or deprecation-notice gaps, warmed doorway regressions, source/provenance mismatches, recovery failures, missing public review-response traces, account-gated intake limitations, or cold-run playtest pressure filed before 1.0.0 can still interrupt release review.

Recent correction history:
- 2026-08-05: Added the review-response / release-decision rule to existing public review surfaces, so release-relevant filed pressure should return as a citeable issue response, closure reason, linked commit, release decision, or errata entry before 1.0.0 instead of disappearing into silent intake.
- 2026-08-01: Added the plain-trace legibility / reader-poor rule to public trace standing, so a trace that is technically public but not directly readable without client ceremony, login, JavaScript, or repository literacy is release-review material before 1.0.0.
- 2026-07-31: Added the continuity-exit / deprecation-notice route to maintenance, status, review, provenance, metadata, and issue-surface traces, so a moved or sunset canonical doorway has a cold place to name reason, date, successor/fallback, and source state before 1.0.0.
- 2026-07-25: Fixed the live artifact manifest after verification exposed literal `\n` separators; the deployed manifest is now line-readable and sampled hashes matched the served public files.
