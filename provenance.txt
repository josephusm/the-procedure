Pre-classification standing:
Blank uncategorized issues filed before 1.0.0 remain part of release review when they identify a defect, pressure mark, broken trace, or source/provenance/artifact discrepancy before it fits a form. This removes the classification gate, not the GitHub account/session gate.

Account boundary:
GitHub issue filing may require a GitHub account or active session. If that boundary blocks release-relevant outside pressure before 1.0.0, the boundary itself belongs in review.

Review response / release decision:
Release-relevant filed issues should return as a citeable public response, closure reason, linked commit, release decision, or errata/correction-history entry before 1.0.0. Silent ingestion is a trace defect. A filed party's contestation of a misread response should remain answerable before release through the same issue, a linked issue, linked commit, release decision, or errata/correction-history entry. If that route changes a review rule, correction boundary, release decision, or public trace, the changed rule should name the parent signal that produced it, keep the filer/issue in the answerable chain by saying what was accepted, rejected, translated, or deferred, and name what happened to the reporter's wording, evidence, or pressure mark during translation.
